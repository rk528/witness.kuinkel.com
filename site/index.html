Setuid or Setgid Bit Set With chmod Linux T1548.001 high Awaiting lab capture

Detects chmod adding the setuid or setgid bit, in symbolic (u+s, g+s, +s) or octal (4xxx, 2xxx, 6xxx) form. A setuid copy of a shell or interpreter is a classic way back to root. Everyday permission changes such as chmod +x or chmod 755 do not match.

Sigma rule · Evidence

Recorded attack it must catch

Not recorded yet. The rule only counts as proven once scripts/capture.ps1 has recorded the real attack in the lab and the rule fires on every recorded test.

Normal activity it must ignore

ResultScenarioCommand line
QuietMaking a script executablechmod +x deploy.sh
QuietOwner-only execute bit (u+x, not u+s)chmod u+x build.sh
QuietStandard 755 on an app scriptchmod 755 /opt/app/run.sh
QuietRecursive 0750 on a data folderchmod -R 0750 /srv/data
QuietConfig file to 644chmod 644 /etc/nginx/nginx.conf

Ready-to-run queries

Microsoft Sentinel (ASIM, KQL)
imProcessCreate
| where TargetProcessName endswith "/chmod" and ((TargetProcessCommandLine contains "u+s" or TargetProcessCommandLine contains "g+s" or TargetProcessCommandLine contains "ug+s" or TargetProcessCommandLine contains " +s " or TargetProcessCommandLine contains "a+s") or TargetProcessCommandLine matches regex "(^|/|\\s)chmod\\s+(-\\S+\\s+)*0?[246][0-7]{3}\\s")
Microsoft Defender XDR (KQL)
DeviceProcessEvents
| where FolderPath endswith "/chmod" and ((ProcessCommandLine contains "u+s" or ProcessCommandLine contains "g+s" or ProcessCommandLine contains "ug+s" or ProcessCommandLine contains " +s " or ProcessCommandLine contains "a+s") or ProcessCommandLine matches regex "(^|/|\\s)chmod\\s+(-\\S+\\s+)*0?[246][0-7]{3}\\s")
Splunk (Sysmon, SPL)
sourcetype="sysmon:linux" EventCode=1 Image="*/chmod"
| rex field=CommandLine "(?<CommandLineMatch>(^|/|\\s)chmod\\s+(-\\S+\\s+)*0?[246][0-7]{3}\\s)"
| eval CommandLineCondition=if(isnotnull(CommandLineMatch), "true", "false")
| search CommandLine IN ("*u+s*", "*g+s*", "*ug+s*", "* +s *", "*a+s*") OR CommandLineCondition="true"
Shell History File Deleted or Emptied Linux T1070.003 medium Awaiting lab capture

Detects rm, shred, truncate or ln being pointed at a shell history file. Wiping .bash_history or linking it to /dev/null is how intruders hide the commands they ran. Reading the file (cat, less, grep) is ignored, so analysts reviewing history stay quiet.

Crontab Installed From a Temporary Folder Linux T1053.003 medium Awaiting lab capture

Detects crontab loading a whole new table from a file in /tmp, /var/tmp or /dev/shm. Malware writes its schedule to a world-writable folder and installs it in one step for persistence. Editing with crontab -e or listing with -l never names such a file.

Interactive Shell Redirected Over /dev/tcp Linux T1059.004 high Awaiting lab capture

Detects a command line that opens a bash /dev/tcp or /dev/udp socket and redirects the shell's input or output through it, the shape of a reverse shell. Opening /dev/tcp on its own is a common port check in health scripts, so the rule also requires a file descriptor redirection (>&, <&) before it fires.

File Download With certutil Windows T1105 high Awaiting lab capture

Detects certutil.exe fetching a remote URL with -urlcache or -verifyctl. certutil is signed by Microsoft and present on every Windows host, so it is a favourite way to pull a second stage past application allow-listing. Requiring a URL scheme keeps routine cache maintenance such as "certutil -urlcache * delete" quiet.

LSASS Memory Dump via comsvcs.dll MiniDump Windows T1003.001 high Awaiting lab capture

Detects rundll32 calling the MiniDump export of comsvcs.dll, a built-in way to dump LSASS memory without bringing any tools. PowerShell Launched With an Encoded Command Windows T1059.001 T1027 medium Awaiting lab capture

Detects powershell.exe or pwsh.exe started with -EncodedCommand or one of its short forms. Encoding hides the real script from command-line logging, which is why loaders and C2 stagers use it. The flag list deliberately leaves out "-enco": it also matches "-Encoding" inside ordinary -Command scripts and was the main source of noise.

Scheduled Task Created to Run From a User-Writable Folder Windows T1053.005 medium Awaiting lab capture

Detects schtasks /create where the task runs something out of Temp, Public or the roaming profile. Malware drops its payload where any user can write and then adds a task for persistence. AppData\Local as a whole is left out on purpose: OneDrive, Teams and other per-user updaters legitimately schedule tasks from there.

Shadow Copies or Backup Catalog Deleted Windows T1490 high Awaiting lab capture

Detects the commands ransomware runs just before encrypting, to stop the victim rolling back: deleting Volume Shadow Copies with vssadmin, wmic or PowerShell, deleting the Windows Backup catalog, and turning off boot recovery with bcdedit. Read-only commands such as "vssadmin list shadows" or "bcdedit /enum" do not match.
